# 记忆时间轴（第三档批次 1，2026-11-09 / 11-12 收尾）

> 方向文档：`2026-11-02-next-phase.md`。本文件是这一批的**执行记录**。

## Goal

让她知道"这是哪天的事"，不再把上周的约定说成明天。

**起点（10-31 实测）**：用户说「今天有点累，刚下课」，她回
> （嗯了一声）那就别硬撑着聊。（停顿一下）**明天三点半**，撑得住就来，撑不住也别勉强。

而"明天三点半"来自 **9 天前**的长期记忆。根因：`long_memory` 是 `list[str]`，
没有任何时间信息，模型看到「明天下午三点集合」无从判断是哪天的"明天"。

## 做法（零 schema 迁移）

不改 `list[str]` 结构 —— 改成 `list[{text, at}]` 要同步迁移真源、索引、导出、
记忆编辑页和一堆测试，收益一样但风险大一个数量级。

| 层 | 文件 | 改动 |
|---|---|---|
| 纯函数 | `funcation/memory_timeline.py`（新） | `stamp` / `strip_stamp` / `prefix_of` / `date_of` / `same_memory` / `with_same_date` / `defuse_relative_time` |
| 写 | `memory_center.py` | `add_long_memory` 加 `（YYYY-MM-DD）` 前缀、按**正文**去重；`update/delete` 改前缀无关匹配、更新沿用原日期 |
| 写（治本） | `memory_agent.py` | 提取规则**禁止相对时间**，要写就写绝对日期，不知道日期就不写时间 |
| 读 | `prompt.py` | 每条记忆加显式时间标签；相对时间「去活化」；旧安排逐条附硬提示；规则 + ❌ 错误示范 |
| 测试 | `test_memory_timeline.py`（新）25 条 | 纯函数 / 三个写方法 / 渲染层 / 提取端规则 |
| 测试 | `test_memory_source_of_truth.py` | 断言改用 `_bodies()` 比正文 + 加日期断言；**embedding 换成本地确定性 hash 向量** |

### 两个必须记住的坑

1. **`update` / `delete` 原本按文本完全相等匹配**。加前缀后 LLM 返回的
   `old_memory` 不会精确复现「（2026-10-30）」→ **更新静默失败**。
   所有"找一条记忆"的地方必须走 `same_memory()`。
2. **只加前缀 + 一句说明没用**。实测四轮打脸记录见下。

### 顺带修的测试环境问题

`test_memory_source_of_truth.py` 故意用真 chromadb，但 embedding 走 FastEmbed
（每次构造都访问 huggingface.co）。网络 502 时**整个文件卡到超时**（实测 540s 没跑完）。
现在在它的 `mc` fixture 里把 embedding 换成本地 sha256 确定性向量：
真 sqlite / 真 collection / 真增删查全部保留，只去掉外网依赖。
⚠️ `HF_HUB_OFFLINE=1` **不能**当解法 —— 本机没模型缓存时反而会让这些测试直接失败。

## 实测四轮（真 LLM、真数据，每轮都还原）

注入一条 9 天前的约定 `（2026-10-31）我们约好明天下午三点在图书馆门口集合，他说别迟到。`，
另外库里本来就有 **3 条无日期老记忆**含「明天三点半后勤门口见」这类相对时间。

| 版本 | 「今天有点累」 | 「这两天没什么事吧」 | 「接下来有什么安排吗」 | 「明天要做什么」 | 复发率 |
|---|---|---|---|---|---|
| V1 只加日期前缀 + 温和说明 | ⚠️ 明天再说 | ⚠️ 明天三点半 | — | — | 2/2 |
| V2 每条加标签 + 规则写硬 | ✅ | ⚠️ | ⚠️ | — | 2/3 |
| V3 去活化相对时间 | ✅ | ✅ | ⚠️ | — | 1/3 |
| **V4 + 逐条硬提示 + 提取端禁相对时间** | ✅ | ✅ | ✅ | ⚠️ | **1/4** |

V4 那一次：
> （干脆地）三点半后勤门口，谈定赔付的事，然后我去趟电影院那边踩点。（看你一眼）你明天来不来，现在给我个准话。

## 已知限制（如实写，不假装修完）

用户**直接问「明天要做什么」**这种最强诱导下，模型仍可能从老记忆里拼出具体安排。
这是 LLM 遵循度 + 历史脏数据的组合，prompt 层压不到 100%。

**根治路径**：清洗历史 `.rag.json`，把含相对时间的记忆改成绝对日期或删除。
这是**改用户数据**，动之前必须先确认（备份 + 列出受影响条目 + 逐条确认）。
不在本次范围内。

好消息是**新数据不会再产生这个问题**：`memory_agent` 已禁止相对时间，
`add_long_memory` 会打日期前缀。老数据随时间被挤出去后，问题自然收敛。
